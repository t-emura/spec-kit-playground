# Feature Specification: Standalone Mode

**Feature Branch**: `004-standalone-mode`  
**Created**: 2026-03-29  
**Status**: Draft  
**Input**: 配布時にWebとAPIを単一プロセスへ統合し、利用者視点で1アプリとして起動・利用できるStandalone構成へ移行する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - シングルコマンド起動 (Priority: P1)

利用者がアプリケーションをダウンロードし、コマンド1つで全機能が使える状態にする。現在はAPIサーバーとWebサーバーを別々に起動する必要があり、利用者にとって煩雑な手順が発生している。Standaloneモードでは1コマンドで起動し、ブラウザで即利用できる。

**Why this priority**: 配布・利用開始の摩擦を最小化することがこの機能の核心であり、他のすべての価値はここから派生する。

**Independent Test**: コマンド1つでアプリを起動し、ブラウザでUIが表示され、ノートの作成・保存・読み込みが完結することで検証可能。

**Acceptance Scenarios**:

1. **Given** アプリがインストールされた環境で、**When** `npm start`（または同等のコマンド）を1回実行したとき、**Then** APIとWebの両機能が立ち上がり、ブラウザでアクセスできる状態になる
2. **Given** アプリが起動中に、**When** ユーザーがブラウザでアプリURLを開いたとき、**Then** UIが表示され、ノートの作成・編集・保存がすべて動作する
3. **Given** アプリが起動中に、**When** ユーザーが別のポートや追加プロセスを起動せずに操作したとき、**Then** すべての機能が単一アクセスポイントから利用できる

---

### User Story 2 - データの永続化と再起動後の継続利用 (Priority: P2)

利用者がアプリを停止・再起動した後も、作成したノートやデータが保持されている。Standalone構成ではデータ保存先がどこかを利用者が意識しなくても、標準的な場所に自動保存される。

**Why this priority**: データロストは利用継続の障壁となる。起動の簡易さと同等に重要なユーザー体験。

**Independent Test**: ノートを作成してアプリを停止し、再起動後に同じデータが表示されることで独立して検証可能。

**Acceptance Scenarios**:

1. **Given** アプリが起動し複数のノートが作成済みの状態で、**When** アプリを正常停止・再起動したとき、**Then** 以前作成したすべてのノートとその内容が引き続き利用できる
2. **Given** アプリが動作中に、**When** データが自動的に保存されたとき、**Then** 利用者がデータ保存を手動で操作することなく変更が永続化されている

---

### User Story 3 - 起動失敗時のわかりやすいエラー通知 (Priority: P3)

起動に失敗する場合（例: ビルド成果物が見つからない、DB書き込み権限がない、非Electron CLIモードでのポート競合など）、利用者が原因を把握して解決できるよう、わかりやすいメッセージが表示される。Electronモードではポート自動割り当て（`port: 0`）のため EADDRINUSE は発生しないが、STATIC_DIR 不在・DB 権限不足を主な対象とする。

**Why this priority**: P1・P2が動作した後の品質向上。起動失敗時の利用者体験を改善する。

**Independent Test**: 使用中のポートでアプリ起動を試みたとき、明確なエラーメッセージが出力されることで検証可能。

**Acceptance Scenarios**:

1. **Given** 指定ポートが既に別プロセスで使用中の状態で、**When** アプリを起動しようとしたとき、**Then** ポート競合を示す明確なメッセージと解決手順が表示され、プロセスはクリーンに終了する
2. **Given** アプリが起動できなかった場合に、**When** エラーが発生したとき、**Then** 利用者にわかりやすい言葉でエラー内容が伝わり、技術的な詳細は別途ログで確認できる

---

### Edge Cases

- アプリ起動中に強制終了（Ctrl+C など）した場合、データが破損しないか？
- データ保存先ディレクトリへの書き込み権限がない場合、起動時にどう通知するか？
- 既存の2プロセス構成（開発環境）でのワークフローは引き続き利用できるか？
- デフォルトポートが使用中の場合、別ポートへの自動フォールバックまたは明示的なエラーを出すか？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは単一コマンドの実行によってWebフロントエンドとAPIバックエンドの両機能を起動しなければならない
- **FR-002**: システムはWebフロントエンドの静的ファイルをAPIサーバーが配信し、利用者が単一のURL（例: `http://localhost:PORT`）でアクセスできなければならない
- **FR-003**: システムはAPIリクエストとWebコンテンツ配信を同一のポートで処理しなければならない
- **FR-004**: システムは起動時にデータ保存先ディレクトリが存在しない場合、自動的に作成しなければならない
- **FR-005**: システムはデータを既定のユーザーデータディレクトリ（OSごとの標準パス）または指定パスに保存しなければならない
- **FR-006**: システムはアプリ停止時（正常終了・割り込みシグナル）にデータの整合性を保った状態でシャットダウンしなければならない
- **FR-007**: システムはポート競合などの起動失敗時に、利用者が理解できるエラーメッセージをコンソールに出力しなければならない
- **FR-008**: 非 Electron CLI 起動時（`npm start`）において、環境変数 `PORT` でポート番号をオーバーライドできなければならない。Electron アプリ起動時はポートを OS に自動割り当て（`port: 0`）するため、このオーバーライド要件は Electron モードには適用しない
- **FR-009**: 既存の開発環境向け2プロセス起動方式（`npm run dev`）は引き続き利用可能でなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めてアプリを起動するユーザーが、ドキュメントを読まずにコマンド1つでアプリを起動し全機能を利用できる
- **SC-002**: アプリの起動から最初のノート作成完了まで30秒以内に達成できる
- **SC-003**: アプリの再起動後、以前に保存したすべてのデータが100%の再現性で利用可能である
- **SC-004**: 起動エラーが発生した場合、100%のケースで原因と解決策を示すメッセージが表示される
- **SC-005**: 既存の開発向けワークフロー（2プロセス起動）が変更なく引き続き動作する

## Assumptions

- 配布対象はデスクトップ環境（macOS・Windows・Linux）を想定し、モバイルデプロイは対象外
- 利用者は1人（シングルユーザー）を想定し、複数ユーザーの同時利用・認証機能は対象外
- データはローカルファイルシステムに保存し、クラウド同期・バックアップ機能は対象外
- ポート番号のデフォルト値は既存の設定（APIのデフォルトポート）を踏襲する
- WebフロントエンドはビルドされたSPAとして配信され、開発時のホットリロードはStandaloneモード外
- 既存のAPIとWebのソースコードに大きな変更は行わず、エントリーポイント・ビルド設定の変更で対応する
